[Bun 1.4.4](https://bun.sh/blog/bun-v1.4.4), released on 2026-10-22, adds `bun fmt`, a code formatter that Bun describes as Prettier-compatible. The release also changes how `bun install` migrates lockfiles and retries requests, and rewrites Bun's built-in `ws` module{% include cite.html n=1 %}.

## `bun fmt`

`bun fmt` is a port of Prettier that reads existing Prettier and oxfmt config files and accepts the same command-line flags{% include cite.html n=1 %}. `--check` exits with code 1 if any file needs formatting, and `--staged` formats and re-stages files for a pre-commit hook{% include cite.html n=1 %}. If a config uses a plugin `bun fmt` doesn't support, it skips the files that plugin covers and exits with code 2{% include cite.html n=1 %}.

Bun says the output matches Prettier 3.9.9 on 99.1% of Prettier's own tests, and on 77.0% of the 74 open-source projects it compared byte for byte{% include cite.html n=1 %}.

## `bun install`

`bun install` now converts a Yarn 2+ (Berry) `yarn.lock` to `bun.lock` and keeps every pinned version; 1.4.3 migrated only Yarn v1 lockfiles{% include cite.html n=1 %}. The migration is all-or-nothing: if Bun can't preserve a pin, such as an `exec:` dependency, it resolves from `package.json` instead{% include cite.html n=1 %}.

Failed requests are still retried up to five times, but now with exponential backoff from 50 ms, where 1.4.3 used up all five retries within 5 ms{% include cite.html n=1 %}. `Retry-After` headers are respected, and `BUN_CONFIG_HTTP_RETRY_BACKOFF=0` restores immediate retries{% include cite.html n=1 %}.

## `ws` now behaves like npm's `ws`

Bun's built-in `ws` is rewritten as a port of `ws` 8.22.0, and Bun says it now passes 234 of that package's 271 tests, up from 94{% include cite.html n=1 %}.

## Behavior changes

- Unknown flags to `bun install` and other package-manager commands are now errors, so a typo like `--frozen-lockfil` no longer runs a normal install in CI{% include cite.html n=1 %}.
- An unhandled `'error'` event on a `ws` socket is now an uncaught exception, and `ws` servers no longer inherit `Bun.serve`'s 120-second idle timeout{% include cite.html n=1 %}.
- Glob patterns such as `*(1).txt`, `!(g)/a.ts`, and `{1..3}` are now extglob and brace-range syntax, not literal text{% include cite.html n=1 %}.
- TLS servers request a client certificate only when `requestCert: true` is set; `ca` alone no longer does{% include cite.html n=1 %}.

## What to do

Our advice: upgrade, because 1.4.4 includes security fixes for TLS, WebSocket, the database clients, and the package manager{% include cite.html n=1 %}. Then check CI scripts for install flags that are now rejected, add an `'error'` listener to every `ws` client and server socket as Bun advises, and set `requestCert: true` alongside `ca` for mutual TLS{% include cite.html n=1 %}.
