Anthropic released Claude API version `2026-10-21` on 2026-10-21, together with new major versions of its client SDKs and `ant` CLI that send it by default, according to its [API release notes](https://docs.claude.com/en/release-notes/api). They are Python SDK 2.0.0, TypeScript SDK 1.0.0, C# SDK 13.0.0, Go SDK 2.0.0, Java SDK 3.0.0, PHP SDK 1.0.0, Ruby SDK 2.0.0, and `ant` CLI 2.0.0{% include cite.html n=1 %}. The new versions also carry breaking changes that don't depend on the API version, and they move from the MIT License to Apache 2.0{% include cite.html n=1 %}.

## Who has to act

Anthropic's [migration guide](https://docs.claude.com/en/api/migration-2026-10-21) says each SDK major version sends the API version current at its release; earlier ones sent `2023-06-01`. So the change reaches you when you bump to a new major version, including its Amazon Bedrock and Google Cloud clients, or when you set the `anthropic-version` header to `2026-10-21` yourself{% include cite.html n=2 %}.

## What breaks in the API

- **Sampling parameters.** On the Messages API, token counting, and Message Batches, sending `temperature`, `top_p`, or `top_k` returns a 400 error, even at the default value{% include cite.html n=2 %}. Claude 4.7 and later models already accept only the defaults, but on models such as Claude Sonnet 4.6, a lowered `temperature` loses its effect, and no other setting replaces it{% include cite.html n=2 %}.
- **Message content.** A `document` block placed directly in an `assistant` message returns a 400 error, and so does a non-empty `citations` array on a `text` block in a `user` message{% include cite.html n=2 %}.
- **Admin and Analytics APIs.** Responses no longer include the old names of renamed fields, for example `roles` (now `role_ids`) and `actor.email` (now `actor.email_address`){% include cite.html n=2 %}. API keys drop `workspace_id` in favor of `scope`, and code that treated a `null` `workspace_id` as the Default Workspace must compare `scope.workspace_id` with that workspace's ID instead{% include cite.html n=2 %}.

## What breaks in the SDKs and CLI

- The SDK and CLI send the API key as `Authorization: Bearer <key>` instead of `X-Api-Key`, so proxies, gateways, middleware, log filters, and test stubs that read `X-Api-Key` need updating{% include cite.html n=2 %}.
- In every SDK, `MessageParam` splits into per-role types; in the C#, Go, Java, PHP, and Ruby SDKs, one-value enums also become constants{% include cite.html n=2 %}.
- Text Completions is gone from the TypeScript, Go, Java, and Ruby SDKs and the CLI, and the TypeScript and Ruby tool runners drop client-side compaction{% include cite.html n=2 %}.
- `ant` no longer accepts `--api-key` or `--auth-token`{% include cite.html n=2 %}.

## What to do

Upgrade to the new major version, fix each breaking change that affects you, test against `2026-10-21`, and release the upgrade and the fixes together{% include cite.html n=2 %}. If a request depends on a non-default `temperature`, the guide says to stop sending it or keep that request on `2023-06-01`{% include cite.html n=2 %}. If you track dependency licenses, update the entries; no code changes are needed for the license move{% include cite.html n=2 %}.

## What's still unclear

Neither source says how long `2023-06-01` remains supported, or how to keep a single request on it while using a new SDK major{% include cite.html n=1 %}{% include cite.html n=2 %}.
